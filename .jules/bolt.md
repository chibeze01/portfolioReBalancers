## 2024-03-28 - [Backend Yahoo Finance Bulk Download]
**Learning:** The application was experiencing an N+1 problem in `analytics_service` and `rebalance_service` because `get_price(h.symbol)` was called in a loop for each holding in a portfolio, triggering individual HTTP requests to Yahoo Finance for every ticker. This was not ideal and caused serious performance bottlenecks when calculating portfolio summaries.
**Action:** Implemented `get_prices_batch` in `server/app/pricing/yahoo_provider.py` using `yfinance.download(symbols_string, period="1d")` to batch requests. Replaced individual fetches in domain services with upfront bulk fetches. When optimizing similar pricing operations, always check if bulk retrieval capabilities exist for the upstream API/provider.

## 2026-04-25 - Efficient Frontier N+1 Optimization
**Learning:** `_load_portfolio_data` inside `efficient_frontier_service.py` was fetching prices sequentially in a loop causing major latency for larger portfolios. Replacing it with `yahoo_provider.get_prices_batch` prevents N+1 issues and matches similar optimizations in `analytics_service.py`. It is crucial to retain `stub_get_price` fallback logic on a per-symbol basis after a batched call, rather than eagerly resolving all stubs. Also, never commit binary database files generated by tests.
**Action:** Always scan loops for repetitive network calls when looking for performance wins. Safely combine them into batch calls upstream. Verify that local testing artifacts (like `test.db`) are cleaned up or ignored by Git before committing.
