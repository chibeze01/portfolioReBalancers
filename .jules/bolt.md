## 2024-06-25 - Batch Network Calls for Provider APIs
**Learning:** The `yahoo_provider.py` does sequential API calls in `analytics_service`, `efficient_frontier_service`, and `recommendation_service` via `get_historical_prices` and `get_stock_info`. This is a classic N+1 bottleneck, making endpoints like `portfolio_historical` and `compute_efficient_frontier` extremely slow (e.g. 1.5s vs 0.16s for 10 assets).
**Action:** Implemented `get_historical_prices_batch` and `get_stock_info_batch` in `yahoo_provider.py` using `ThreadPoolExecutor` and replaced sequential calls in the domain services with these batch equivalents to parallelize the network operations.
## 2024-06-25 - Fix Symbol Casing in Batch Responses
**Learning:** When looking up symbols in batched pricing responses (e.g., `get_stock_info_batch`), always cast the lookup symbol to uppercase (e.g., `symbol.upper()`) to match the standardized uppercase keys returned by `yahoo_provider.py` and prevent case-sensitivity bugs. Not doing this causes silent `None` returns, which can break services that depend on the data.
**Action:** When creating batch network requests and responses using a dictionary where the keys are symbols, always uppercase the keys and uppercase the symbols during dictionary lookup.
