## 2024-03-28 - [Backend Yahoo Finance Bulk Download]
**Learning:** The application was experiencing an N+1 problem in `analytics_service` and `rebalance_service` because `get_price(h.symbol)` was called in a loop for each holding in a portfolio, triggering individual HTTP requests to Yahoo Finance for every ticker. This was not ideal and caused serious performance bottlenecks when calculating portfolio summaries.
**Action:** Implemented `get_prices_batch` in `server/app/pricing/yahoo_provider.py` using `yfinance.download(symbols_string, period="1d")` to batch requests. Replaced individual fetches in domain services with upfront bulk fetches. When optimizing similar pricing operations, always check if bulk retrieval capabilities exist for the upstream API/provider.
## 2024-04-17 - [Efficient Frontier Pricing Fallback Architecture]
**Learning:** In the backend `domain/services`, fixing N+1 pricing requests should not bypass the existing pricing abstraction logic. Instead of calling `yahoo_provider` directly, use the `stub_provider.get_prices` abstraction. It serves as a facade, efficiently batch-fetching from Yahoo and correctly applying the pseudo-price fallback logic *only* for the specific symbols that failed, keeping the system safe from N+1 without breaking its designed fallback mechanism.
**Action:** When optimizing domain service loops that fetch prices, always leverage `stub_provider.get_prices(symbols)` to get the batched prices, preserving the exact behavior of `_get_price` for each symbol while significantly improving performance.
