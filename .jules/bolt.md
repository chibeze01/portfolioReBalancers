## 2024-03-28 - [Backend Yahoo Finance Bulk Download]
**Learning:** The application was experiencing an N+1 problem in `analytics_service` and `rebalance_service` because `get_price(h.symbol)` was called in a loop for each holding in a portfolio, triggering individual HTTP requests to Yahoo Finance for every ticker. This was not ideal and caused serious performance bottlenecks when calculating portfolio summaries.
**Action:** Implemented `get_prices_batch` in `server/app/pricing/yahoo_provider.py` using `yfinance.download(symbols_string, period="1d")` to batch requests. Replaced individual fetches in domain services with upfront bulk fetches. When optimizing similar pricing operations, always check if bulk retrieval capabilities exist for the upstream API/provider.
## 2024-03-29 - [Optimize Recommendation Service Portfolio Sectors Analysis]
**Learning:** In the `_analyze_portfolio_sectors` method of `recommendation_service.py`, stock information was fetched sequentially in a loop using `get_stock_info`. Since fetching stock info involves HTTP requests to Yahoo Finance, this caused a significant N+1 performance bottleneck when analyzing portfolios with multiple holdings.
**Action:** Implemented a `get_stock_info_batch` method in `yahoo_provider.py` utilizing `ThreadPoolExecutor` to fetch extended stock information concurrently. When dealing with repeated I/O bound calls like fetching stock info within loops across the codebase, always check if a batched version exists or create one to avoid sequential latency. Be sure to account for caching and case-sensitivity (always `symbol.upper()`) in batched methods.
